# 研发汇报场景手册

## 1. 周报 / 月报 / 向上进展

适用：向负责人说明本周期项目状态、风险和决策需求。

推荐顺序：**一句话总体判断 → 关键成果及业务意义 → 风险/阻塞 → 下周期计划 → 需要支持的事项**。

页级示例：
1. 版本核心功能按计划推进，但一项性能验证仍未完成
2. 已实现的关键能力已覆盖指定测试场景（写清覆盖范围）
3. 当前阻塞集中在环境稳定性与测试资源
4. 下周计划优先完成验证，再推进发布评审

避免把“提交了10次代码”“修复了8个缺陷”当作最终价值，除非能对应明确的产品质量、风险或交付效果。

## 2. 技术方案评审 / 立项答辩

推荐顺序：**问题与约束（病）→ 备选方案与选型依据（药）→ 预期收益和成功标准（效）→ 技术证据/验证计划（托）→ 风险、回退、决策请求**。

至少准备：约束条件、取舍对比、性能容量、安全影响、兼容性、上线与回退、成本和验证边界。未测试的内容只能称预期，不可称已验证。

## 3. 线上故障复盘 / 根因说明

推荐顺序：**结论与当前状态 → 现象及影响范围 → 事实时间线 → 已验证根因/尚存假设 → 处置及验证 → 预防措施、责任与验收条件**。

保留“病药效托”的精神，但不强求先销售方案再讲证据。清晰区分触发因素、根因、放大因素；对未证实根因写“待验证”。

## 4. 对外客户 / 产品方案介绍

优先使用：**客户场景与痛点（病）→ 解决方案总体打法（药）→ 可量化效果或预期收益（效）→ 可公开案例与数据（托）→ 试点及合作下一步**。

提醒脱敏客户名称、拓扑、漏洞、账号、日志和授权边界。竞品比较只使用可核实、口径一致的数据。

## 5. 短时口头汇报

- 30秒：结论（1句）→ 最重要依据（1句）→ 下一步（1句）。
- 3分钟：结论 → 2—3个关键事实 → 风险与诉求。
- 10分钟：主要结论 → 病药效托/场景骨架 → 数据 → 风险 → 下一步。

所有时长均为建议，可根据听众和场合灵活调整。

## 页级提纲格式

| 页 | 观点式标题 | 论据（不超过3组） | 建议图表 | 本页落脚点 | 缺失证据 |
|---|---|---|---|---|---|
| 1 | [可判断的结论] | [事实A/B/C] | [对比/趋势等] | [意义与动作] | [待补] |

完成后串读所有“观点式标题”，检验是否形成连续故事。
