# 追问与答辩手册

## 四步动作

1. **接住**：确认问题，“您关注的是上线后是否会再次影响其他任务，对吗？”
2. **拆解**：识别底层顾虑，“这涉及并发控制、容量上限和异常回退三个方面。”
3. **应答**：先给已有结论和事实，“目前可以确认并发限制已加入；跨机器容量边界还需专项测试。”
4. **锁下一步**：“我会补充不同核数与任务数量下的压测结果；具体提交时间需与测试方确认。”

## 高频追问维度

| 类型 | 评委可能问什么 | 应准备哪些证据 |
|---|---|---|
| 必要性 | 为什么现在必须做？ | 问题影响与不做代价 |
| 方案选择 | 为什么不采用另一种技术？ | 备选方案取舍表 |
| 有效性 | 你凭什么说有效？ | 基线、样本、测试方法、数值 |
| 规模与边界 | 高并发、大数据量、旧版本是否成立？ | 边界测试和已知限制 |
| 风险 | 失败怎么办，如何回滚？ | 回退路径、开关、监控 |
| 排期与资源 | 什么时候完成，为什么要人？ | 关键路径、资源约束 |
| 业务价值 | 客户或业务到底受益什么？ | 可核实的结果及影响 |

## 无法当场回答时

推荐：
> 这个问题我先回答已确认的部分：……。另一个部分目前没有足够数据，我不想现场给出不准确的结论。建议按……方式补充验证，形成结果后同步；完成时间还需要确认。

禁止：
- 编造性能提升百分比或用户案例。
- 无依据地承诺“绝对没有风险”。
- 只有“我回去看看”，却没有补证据路径。

## 模拟评审模式

用户要求“模拟”时，优先一次一个问题：
1. 基于用户材料挑一个最可能影响放行的高风险问题。
2. 只发问题，不提前发参考答案。
3. 用户回答后评估：是否答中本质、是否给结论、证据是否足够、是否明确边界、是否锁下一步。
4. 给出可直接复述的改进答案，再追问下一个难点。

用户要求一次性交付题库时，可按“高/中/低风险”一次输出完整问题、答法与证据缺口。
