# 提交前敏感信息检查清单

| 类别 | 高风险示例 | 容易误判的情形 | 处理建议 |
|---|---|---|---|
| 凭据 | 有真实赋值的 password/token、私钥、含口令的数据库 URL | `password` 字段名、`YOUR_TOKEN` | 阻断真实值；改用环境变量或占位符 |
| 地址 | 真实内网服务器地址、内部 DNS、可关联到生产环境的公网 IP | `127.0.0.1`、`192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24` | 私有部署信息阻断；不确定的公网地址待确认 |
| 企业客户 | 未公开的公司/客户名、内部部门、专有项目代号 | 明确公开且与业务泄密无关的名称 | 私有身份阻断；公开身份需判断关联上下文 |
| 人名 | 同事、客户联系人、客户现场人员真实姓名 | 通用虚构示例、公开作者署名 | 与内部业务关联则阻断，否则待确认 |
| 联系方式 | 真实手机号、企业邮箱、个人邮箱 | `name@example.com` | 脱敏或替换示例 |
| 配置文件 | `.env`、密钥、包含真实环境值的 YAML/JSON/INI | `.env.example` 且全部为虚构值 | 检查文件内容，敏感则阻断 |
| 文档截图 | 现场日志、内部服务结构、真实账号或人名 | 脱敏后的示意图 | 对不可读附件保持保守，必要时人工复核 |

## 重要原则

1. 不要把「未匹配到正则」当成「没有敏感信息」。
2. 仓库是公开仓库时，严查 README、技能说明、参考材料和示例日志。
3. 不应把用户的敏感词库放进这个公开技能目录。可在本地私有文件中维护，并在扫描时读取，但绝不自动提交。
4. 仅检查当前提交不等于清理 Git 历史；已经提交过的凭据要撤销、轮换，并单独处理历史记录。
5. 即使本技能审查通过，人工直接操作 Git 或自动化流程也不会因此受到保护。
