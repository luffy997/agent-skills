# 示例：安全实时预警

原始需求：“安全实时预警”不要太快轮询，格式为代码缺陷+系统名称，低危不用展示了。

第一轮至少识别：
- Q-001：轮询间隔到底是 30、60、120 秒还是自定义？（推荐 60 秒仅为建议）
- Q-002：代码缺陷的展示字段是名称、类型还是描述？如系统有多个字段，结合现状提供候选。
- Q-003：系统名称来自所属应用、项目还是资产系统？如只有一个明确字段，可展示项目事实并请用户确认。
- Q-004：只排除低危还是连信息级也排除？
- Q-005：过滤是在实时预警模块中，还是同时影响历史/统计？

后续视用户答案追问：采用前端还是后端筛选（若对结果、数据泄漏或接口契约有影响）、轮询失败是否重试、预警为空如何显示、是否要防并发请求。

注意：不得直接将“60 秒、只过滤低危、前端过滤、SQL 注入 - 资产管理系统”写成已经确认的要求；这些只是样例。确认完成后再给出具体研发任务。
